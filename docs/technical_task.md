# Техническое задание

## Тема проекта

Разработка веб-ориентированной информационной системы для кофейни.

## Назначение системы

Информационная система предназначена для автоматизации основных процессов кофейни: регистрации клиентов, просмотра меню, оформления предварительных заказов, учета истории заказов, работы с бонусной программой, использования реферальной программы, отображения акций и публикации информации о кофейне.

Система должна быть понятной для пользователей и удобной для администраторов кофейни. Проект реализуется в рамках дипломной работы и должен демонстрировать применение современных средств веб-разработки, серверной архитектуры и работы с базой данных.

## Цели разработки

Основные цели проекта:

- создать централизованную информационную систему для кофейни;
- обеспечить регистрацию и авторизацию пользователей;
- реализовать личный кабинет клиента;
- предоставить клиентам доступ к меню кофейни;
- реализовать оформление предварительных заказов;
- хранить историю заказов;
- реализовать бонусную программу лояльности;
- реализовать реферальную программу;
- предоставить пользователям информацию об акциях;
- предоставить информацию о расположении кофейни;
- создать административные функции для управления данными.

## Пользователи системы

Система рассчитана на следующие категории пользователей:

- гость;
- зарегистрированный клиент;
- администратор кофейни.

Гость может просматривать публичную информацию: меню, акции и сведения о кофейне. Зарегистрированный клиент дополнительно может оформлять заказы, просматривать бонусную карту, историю операций и использовать реферальную программу. Администратор управляет меню, заказами, акциями и информацией о кофейне.

## Функциональные требования

### Авторизация и пользователи

Система должна обеспечивать:

- регистрацию пользователя;
- вход пользователя по email и паролю;
- хранение пароля в защищенном виде;
- выдачу JWT access token;
- получение данных текущего пользователя;
- автоматическое создание бонусной карты;
- автоматическое создание уникального реферального кода.

### Меню

Система должна обеспечивать:

- хранение категорий товаров;
- хранение товаров меню;
- просмотр списка категорий;
- просмотр списка доступных товаров;
- просмотр товара по идентификатору;
- административное создание, изменение и удаление товаров;
- административное создание категорий.

### Заказы

Система должна обеспечивать:

- создание заказа пользователем;
- хранение состава заказа;
- сохранение цены товара на момент заказа;
- расчет общей суммы заказа;
- поддержку типов заказа: `offline` и `preorder`;
- поддержку времени получения заказа для предварительных заказов;
- просмотр пользователем своих заказов;
- просмотр конкретного заказа;
- отмену заказа пользователем;
- административное изменение статуса заказа.

Статусы заказов:

- `created`;
- `accepted`;
- `preparing`;
- `ready`;
- `completed`;
- `cancelled`.

### Программа лояльности

Система должна обеспечивать:

- наличие одной бонусной карты у каждого пользователя;
- хранение бонусного баланса;
- просмотр бонусной карты;
- просмотр истории бонусных операций;
- списание бонусов при создании заказа;
- начисление бонусов после завершения заказа;
- сохранение каждой операции начисления и списания.

Правила бонусной программы:

- cashback составляет 5% от суммы заказа;
- бонусы начисляются только после перевода заказа в статус `completed`;
- 1 бонус равен 1 денежной единице;
- бонусами можно оплатить не более 50% суммы заказа;
- бонусы не начисляются на сумму, оплаченную бонусами.

### Реферальная программа

Система должна обеспечивать:

- уникальный реферальный код для каждого пользователя;
- просмотр собственного реферального кода;
- применение чужого реферального кода;
- запрет применения собственного кода;
- запрет повторного применения кода;
- просмотр приглашенных пользователей;
- начисление бонусов после первого завершенного заказа приглашенного пользователя.

Правила начисления:

- пригласивший пользователь получает 100 бонусов;
- приглашенный пользователь получает 50 бонусов;
- операции сохраняются в истории бонусных транзакций.

### Акции

Система должна обеспечивать:

- хранение акций;
- просмотр активных акций;
- просмотр акции по идентификатору;
- административное создание, изменение и удаление акций.

### Информация о кофейне

Система должна обеспечивать:

- хранение названия кофейни;
- хранение адреса;
- хранение координат для отображения на карте;
- хранение телефона;
- хранение режима работы;
- хранение описания;
- хранение изображения;
- хранение ссылок на социальные сети;
- публичный просмотр информации и местоположения;
- административное обновление информации.

## Нефункциональные требования

Система должна соответствовать следующим требованиям:

- серверная часть реализуется на Python с использованием FastAPI;
- база данных — PostgreSQL;
- работа с базой данных выполняется через SQLAlchemy;
- конфигурация хранится в переменных окружения;
- архитектура серверной части должна быть модульной;
- бизнес-логика не должна размещаться непосредственно в роутерах;
- структура должна соответствовать схеме Router -> Service -> Repository -> Database;
- API должно быть документируемым через OpenAPI;
- код должен быть понятным для демонстрации на защите дипломного проекта.

## Требования к окружению

Для запуска проекта используются:

- Python;
- FastAPI;
- PostgreSQL;
- SQLAlchemy;
- Pydantic;
- Docker и docker-compose;
- файл `.env` для настройки окружения.

## Ожидаемый результат

Результатом разработки является веб-информационная система кофейни с серверной частью, базой данных, публичными и административными API-методами, а также документацией, описывающей назначение, архитектуру, структуру данных и бизнес-процессы системы.
