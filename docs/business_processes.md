# Бизнес-процессы

## Общая характеристика

Информационная система автоматизирует основные бизнес-процессы кофейни, связанные с обслуживанием клиентов, обработкой заказов, бонусной программой, реферальной программой, акциями и публикацией информации о заведении.

## Регистрация клиента

Цель процесса — создать учетную запись клиента.

Этапы:

1. Пользователь отправляет email, пароль и данные профиля.
2. Система проверяет корректность email и пароля.
3. Система проверяет, что пользователь с таким email еще не зарегистрирован.
4. Пароль сохраняется в хешированном виде.
5. Создается учетная запись пользователя.
6. Создается профиль пользователя.
7. Создается бонусная карта.
8. Создается уникальный реферальный код.

Результат: пользователь может войти в систему и пользоваться личными функциями.

## Авторизация клиента

Цель процесса — предоставить пользователю доступ к защищенным функциям.

Этапы:

1. Пользователь вводит email и пароль.
2. Система ищет пользователя по email.
3. Система проверяет пароль.
4. При успешной проверке формируется JWT access token.
5. Клиент использует токен для дальнейших запросов.

Результат: пользователь получает доступ к личному кабинету, заказам, бонусам и реферальной программе.

## Просмотр меню

Цель процесса — предоставить клиенту актуальное меню кофейни.

Этапы:

1. Клиент открывает раздел меню.
2. Frontend запрашивает категории и товары.
3. Система возвращает доступные товары.
4. Клиент выбирает товары для заказа.

Результат: клиент получает список товаров с ценой, описанием и доступностью.

## Создание заказа

Цель процесса — оформить заказ клиента.

Этапы:

1. Пользователь выбирает товары и количество.
2. Пользователь выбирает тип заказа: `offline` или `preorder`.
3. Для предварительного заказа может быть указано время получения.
4. Система проверяет доступность товаров.
5. Система рассчитывает итоговую сумму заказа.
6. Система сохраняет позиции заказа.
7. Для каждой позиции сохраняется фактическая цена товара на момент заказа.
8. Если пользователь использует бонусы, система проверяет доступный баланс и ограничение 50%.
9. При использовании бонусов создается транзакция списания.
10. Заказ создается со статусом `created`.

Результат: заказ сохранен в системе и доступен пользователю в истории.

## Обработка заказа администратором

Цель процесса — сопровождение заказа от создания до завершения.

Этапы:

1. Администратор просматривает список заказов.
2. Администратор изменяет статус заказа.
3. Возможные статусы: `created`, `accepted`, `preparing`, `ready`, `completed`, `cancelled`.
4. При переводе в статус `completed` запускаются процессы начисления бонусов.

Результат: заказ проходит полный цикл обработки.

## Начисление бонусов за заказ

Цель процесса — начислить клиенту cashback по программе лояльности.

Правила:

- бонусы начисляются только после завершения заказа;
- cashback составляет 5%;
- бонусы начисляются только на сумму, фактически оплаченную деньгами;
- сумма, оплаченная бонусами, не участвует в начислении;
- каждая операция сохраняется в истории транзакций.

Пример:

```text
Сумма заказа: 1000
Использовано бонусов: 200
База для начисления: 800
Cashback 5%: 40 бонусов
```

Результат: баланс бонусной карты увеличивается, создается запись в `bonus_transactions`.

## Списание бонусов

Цель процесса — дать пользователю возможность оплатить часть заказа бонусами.

Правила:

- 1 бонус равен 1 денежной единице;
- бонусами можно оплатить не более 50% заказа;
- нельзя списать больше бонусов, чем есть на карте;
- каждое списание сохраняется в истории транзакций.

Результат: баланс бонусной карты уменьшается, создается запись списания.

## Реферальная программа

Цель процесса — привлекать новых клиентов через рекомендации существующих пользователей.

Этапы:

1. Каждый пользователь имеет уникальный реферальный код.
2. Новый пользователь вводит код пригласившего пользователя.
3. Система проверяет, что код существует.
4. Система проверяет, что пользователь не применяет собственный код.
5. Система проверяет, что пользователь еще не применял код ранее.
6. После первого завершенного заказа приглашенного пользователя начисляются бонусы.

Правила начисления:

- пригласивший получает 100 бонусов;
- приглашенный получает 50 бонусов;
- бонусы начисляются только один раз;
- операции сохраняются в `bonus_transactions`.

Результат: оба участника получают бонусы после выполнения условий программы.

## Управление акциями

Цель процесса — информировать клиентов о специальных предложениях.

Этапы:

1. Администратор создает акцию.
2. Указывает название, описание, процент скидки, даты начала и окончания.
3. Система отображает только активные акции, попадающие в текущий период.
4. Администратор может изменить или удалить акцию.

Результат: пользователи видят актуальные предложения кофейни.

## Управление информацией о кофейне

Цель процесса — предоставить клиентам актуальные сведения о кофейне.

Этапы:

1. Администратор указывает название, адрес, координаты, телефон, режим работы и описание.
2. Система сохраняет данные.
3. Frontend использует эти данные для страницы информации и карты.

Результат: пользователи могут узнать адрес, режим работы и найти кофейню на карте.
