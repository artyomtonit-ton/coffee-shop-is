# Роли пользователей

## Общая информация

В информационной системе кофейни выделяются несколько категорий пользователей. Каждая категория имеет свой набор возможностей. Разделение ролей необходимо для защиты административных функций и удобной организации пользовательских сценариев.

## Гость

Гость — пользователь, который не прошел авторизацию.

Возможности гостя:

- просматривать меню;
- просматривать категории товаров;
- просматривать информацию о товарах;
- просматривать активные акции;
- просматривать информацию о кофейне;
- просматривать местоположение кофейни.

Ограничения:

- не может создавать заказы;
- не может пользоваться бонусной программой;
- не может применять реферальный код;
- не может просматривать историю заказов;
- не имеет доступа к административным функциям.

## Зарегистрированный клиент

Зарегистрированный клиент — пользователь, который создал учетную запись и выполнил вход в систему.

Возможности клиента:

- просматривать данные своего профиля;
- создавать заказы;
- просматривать свои заказы;
- просматривать конкретный заказ;
- отменять заказ, если он еще не завершен;
- пользоваться бонусной картой;
- просматривать бонусный баланс;
- просматривать историю бонусных транзакций;
- использовать бонусы для частичной оплаты заказа;
- получать бонусы после завершения заказа;
- получать свой реферальный код;
- применять чужой реферальный код;
- просматривать приглашенных пользователей.

Ограничения:

- не может управлять меню;
- не может изменять статусы заказов;
- не может управлять акциями;
- не может изменять информацию о кофейне.

## Администратор

Администратор — сотрудник кофейни, отвечающий за управление данными системы.

Возможности администратора:

- создавать категории меню;
- создавать товары;
- изменять товары;
- удалять товары;
- просматривать все заказы;
- изменять статус заказа;
- создавать акции;
- изменять акции;
- удалять акции;
- обновлять информацию о кофейне.

Ограничения:

- административные действия должны выполняться только уполномоченным пользователем;
- в текущей версии API административные маршруты уже выделены в `/admin`, но полноценная проверка роли администратора должна быть добавлена отдельным этапом развития системы.

## Сравнение возможностей

| Возможность | Гость | Клиент | Администратор |
|---|---:|---:|---:|
| Просмотр меню | Да | Да | Да |
| Просмотр акций | Да | Да | Да |
| Просмотр информации о кофейне | Да | Да | Да |
| Регистрация | Да | Нет | Нет |
| Авторизация | Да | Да | Да |
| Создание заказа | Нет | Да | Нет |
| Просмотр своих заказов | Нет | Да | Нет |
| Использование бонусов | Нет | Да | Нет |
| Реферальная программа | Нет | Да | Нет |
| Управление меню | Нет | Нет | Да |
| Управление заказами | Нет | Нет | Да |
| Управление акциями | Нет | Нет | Да |
| Управление информацией о кофейне | Нет | Нет | Да |

## Перспективы развития ролей

В дальнейшем систему ролей можно расширить:

- добавить таблицу `roles`;
- связать пользователей с ролями;
- реализовать зависимость проверки администратора;
- ограничить доступ к маршрутам `/admin`;
- добавить роль сотрудника, который может только обрабатывать заказы.
