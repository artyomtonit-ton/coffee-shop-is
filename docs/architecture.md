# Архитектура системы

## Общая характеристика

Информационная система кофейни построена как веб-приложение с разделением на серверную часть, клиентскую часть и базу данных. Серверная часть предоставляет REST API, через которое frontend может получать данные, отправлять заказы, выполнять авторизацию и работать с пользовательскими функциями.

Проект использует модульную архитектуру. Каждый функциональный раздел системы расположен в отдельном модуле. Это упрощает сопровождение, тестирование и демонстрацию проекта на защите.

## Технологический стек

Серверная часть:

- Python;
- FastAPI;
- SQLAlchemy;
- Pydantic;
- JWT;
- PostgreSQL.

Инфраструктура:

- Docker;
- docker-compose;
- `.env`-конфигурация.

Клиентская часть:

- React или HTML/CSS/JavaScript;
- адаптивный интерфейс.

## Архитектурный подход

В проекте используется многослойная архитектура:

```text
Router -> Service -> Repository -> Database
```

### Router

Слой маршрутов отвечает за:

- объявление URL-адресов API;
- прием входных данных;
- вызов соответствующего сервиса;
- возврат ответа клиенту.

В роутерах не должна размещаться бизнес-логика.

### Service

Сервисный слой отвечает за:

- выполнение бизнес-правил;
- проверку условий;
- расчет сумм заказов;
- начисление и списание бонусов;
- обработку статусов заказов;
- взаимодействие с несколькими репозиториями при необходимости.

### Repository

Репозиторий отвечает за:

- выполнение запросов к базе данных;
- создание, получение, изменение и удаление записей;
- изоляцию SQLAlchemy-запросов от бизнес-логики.

### Database

Слой базы данных включает:

- SQLAlchemy engine;
- фабрику сессий;
- базовый класс моделей;
- зависимость `get_db` для FastAPI.

## Основные модули backend

### Auth

Модуль авторизации отвечает за:

- регистрацию пользователей;
- вход в систему;
- создание JWT access token.

### Users

Модуль пользователей отвечает за:

- хранение учетных записей;
- хранение профилей;
- получение текущего пользователя;
- хранение реферального кода.

### Menu

Модуль меню отвечает за:

- категории товаров;
- товары меню;
- доступность товаров;
- возможность предварительного заказа.

### Orders

Модуль заказов отвечает за:

- создание заказов;
- хранение состава заказа;
- расчет общей суммы;
- хранение цены товара на момент заказа;
- изменение статусов заказов.

### Loyalty

Модуль лояльности отвечает за:

- бонусные карты;
- бонусный баланс;
- начисления;
- списания;
- историю бонусных операций.

### Referrals

Модуль реферальной программы отвечает за:

- применение реферальных кодов;
- учет приглашенных пользователей;
- начисление реферальных бонусов.

### Promotions

Модуль акций отвечает за:

- хранение акций;
- отображение активных акций;
- административное управление акциями.

### Coffee Shop

Модуль информации о кофейне отвечает за:

- адрес;
- координаты;
- телефон;
- режим работы;
- описание;
- изображение;
- социальные сети.

### Admin

Модуль административных endpoints отвечает за:

- управление меню;
- управление заказами;
- управление акциями;
- управление информацией о кофейне.

## Взаимодействие компонентов

Пользователь взаимодействует с frontend-приложением. Frontend отправляет HTTP-запросы к FastAPI. FastAPI обрабатывает запрос в роутере, передает данные в сервис, сервис обращается к репозиторию, а репозиторий выполняет операции с PostgreSQL через SQLAlchemy.

Пример создания заказа:

```text
Frontend -> POST /orders -> Orders Router -> Order Service -> Order Repository -> PostgreSQL
```

При завершении заказа дополнительно вызываются:

```text
Order Service -> Loyalty Service -> Bonus Transactions
Order Service -> Referral Service -> Referral Bonuses
```

## Безопасность

Для авторизации используется JWT access token. После входа в систему клиент получает токен и передает его в заголовке:

```text
Authorization: Bearer <token>
```

Пароли пользователей не хранятся в открытом виде. Для них используется хеширование.

## Конфигурация

Конфигурация системы хранится в переменных окружения:

- название приложения;
- режим отладки;
- строка подключения к базе данных;
- параметры JWT.

Пример файла конфигурации находится в `.env.example`.

## Преимущества выбранной архитектуры

Выбранная архитектура имеет следующие преимущества:

- понятное разделение ответственности;
- удобство расширения проекта;
- возможность тестирования отдельных слоев;
- соответствие требованиям дипломного проекта;
- удобство демонстрации логики работы системы.
