# Структура базы данных

## Общая информация

В качестве системы управления базами данных используется PostgreSQL. Для взаимодействия приложения с базой данных применяется SQLAlchemy. Основные сущности отражают предметную область кофейни: пользователи, меню, заказы, бонусная программа, реферальная программа, акции и информация о кофейне.

## Основные таблицы

## users

Таблица хранит учетные записи пользователей.

Поля:

- `id` — уникальный идентификатор пользователя;
- `email` — email пользователя, используется для входа;
- `hashed_password` — хеш пароля;
- `referral_code` — уникальный реферальный код пользователя;
- `is_active` — признак активности учетной записи;
- `created_at` — дата и время регистрации.

Связи:

- один пользователь имеет один профиль;
- один пользователь имеет одну бонусную карту;
- пользователь может иметь много заказов;
- пользователь может приглашать других пользователей.

## profiles

Таблица хранит дополнительные данные пользователя.

Поля:

- `id` — уникальный идентификатор профиля;
- `user_id` — ссылка на пользователя;
- `first_name` — имя;
- `last_name` — фамилия;
- `phone` — телефон.

## categories

Таблица хранит категории меню.

Поля:

- `id` — уникальный идентификатор категории;
- `name` — название категории;
- `description` — описание категории.

Связи:

- одна категория может содержать много товаров.

## products

Таблица хранит товары меню.

Поля:

- `id` — уникальный идентификатор товара;
- `category_id` — ссылка на категорию;
- `name` — название товара;
- `description` — описание;
- `price` — цена;
- `image_url` — ссылка на изображение;
- `calories` — калорийность;
- `weight` — вес;
- `volume` — объем;
- `is_available` — доступен ли товар;
- `is_preorder_available` — доступен ли товар для предварительного заказа.

## orders

Таблица хранит заказы пользователей.

Поля:

- `id` — уникальный идентификатор заказа;
- `user_id` — ссылка на пользователя;
- `status` — статус заказа;
- `order_type` — тип заказа;
- `total_amount` — общая сумма заказа;
- `bonus_used` — сумма бонусов, использованная при оплате;
- `bonus_accrued` — сумма бонусов, начисленная за заказ;
- `pickup_time` — время получения заказа;
- `created_at` — дата и время создания.

Допустимые статусы:

- `created`;
- `accepted`;
- `preparing`;
- `ready`;
- `completed`;
- `cancelled`.

Допустимые типы:

- `offline`;
- `preorder`.

## order_items

Таблица хранит состав заказа.

Поля:

- `id` — уникальный идентификатор позиции;
- `order_id` — ссылка на заказ;
- `product_id` — ссылка на товар;
- `product_name` — название товара на момент заказа;
- `quantity` — количество;
- `unit_price` — цена единицы товара на момент заказа;
- `total_price` — итоговая стоимость позиции.

Назначение таблицы — сохранить состав заказа и фактические цены на момент оформления.

## loyalty_cards

Таблица хранит бонусные карты пользователей.

Поля:

- `id` — уникальный идентификатор карты;
- `user_id` — ссылка на пользователя;
- `balance` — текущий бонусный баланс;
- `created_at` — дата создания карты.

Правило: у каждого пользователя должна быть одна бонусная карта.

## bonus_transactions

Таблица хранит историю бонусных операций.

Поля:

- `id` — уникальный идентификатор транзакции;
- `card_id` — ссылка на бонусную карту;
- `order_id` — ссылка на заказ, если операция связана с заказом;
- `transaction_type` — тип операции;
- `amount` — сумма бонусов;
- `description` — описание операции;
- `created_at` — дата и время операции.

Типы операций:

- `accrual` — начисление;
- `write_off` — списание.

## referrals

Таблица хранит факты применения реферальных кодов.

Поля:

- `id` — уникальный идентификатор записи;
- `inviter_id` — пользователь, который пригласил;
- `invited_user_id` — приглашенный пользователь;
- `bonus_awarded` — были ли начислены реферальные бонусы;
- `bonus_awarded_at` — дата начисления реферальных бонусов;
- `created_at` — дата применения кода.

Правило: приглашенный пользователь может применить реферальный код только один раз.

## promotions

Таблица хранит акции кофейни.

Поля:

- `id` — уникальный идентификатор акции;
- `title` — название акции;
- `description` — описание акции;
- `discount_percent` — процент скидки;
- `start_date` — дата начала;
- `end_date` — дата окончания;
- `is_active` — активна ли акция;
- `created_at` — дата создания.

## coffee_shops

Таблица хранит информацию о кофейне.

Поля:

- `id` — уникальный идентификатор записи;
- `name` — название кофейни;
- `address` — адрес;
- `latitude` — широта;
- `longitude` — долгота;
- `phone` — телефон;
- `working_hours` — режим работы;
- `description` — описание;
- `image_url` — ссылка на изображение;
- `social_links` — ссылки на социальные сети.

## Связи между сущностями

Основные связи:

- `users` 1 к 1 `profiles`;
- `users` 1 к 1 `loyalty_cards`;
- `users` 1 ко многим `orders`;
- `categories` 1 ко многим `products`;
- `orders` 1 ко многим `order_items`;
- `loyalty_cards` 1 ко многим `bonus_transactions`;
- `users` 1 ко многим `referrals` как пригласивший пользователь;
- `users` 1 к 1 `referrals` как приглашенный пользователь.

## Особенности хранения данных

Цена товара сохраняется в `order_items` отдельно от таблицы `products`. Это необходимо для корректной истории заказов: если цена товара изменится в меню, старые заказы сохранят исходную стоимость.

Бонусные операции хранятся отдельно от бонусной карты. Это позволяет отследить историю начислений и списаний, а также объяснить пользователю изменение баланса.
